# 会话动态批处理

Giftia 为同一 Bot、同一完整平台会话串行执行决策和回复。群聊、私聊及 `@` 使用相同的合并等待，不需要配置。

按当前已解析入队的消息条数和累计正文字符数分别查表，取较短的等待时间：

| 等待时间 | 消息条数 | 正文字符数 |
| --- | --- | --- |
| 15 秒 | 1 | 0～10 |
| 10 秒 | 2 | 11～30 |
| 6 秒 | 3～4 | 31～60 |
| 3 秒 | 5～7 | 61～100 |
| 1.5 秒 | 8～11 | 101～160 |
| 0.8 秒 | 12 及以上 | 161 及以上 |

正文取原始消息中的文字，忽略空白、`@` 账号与昵称、引用内容、媒体标识和生成的转述。QQ Markdown 提及的重复降级文本只统计一次。纯 `@` 或媒体消息仍各计一条，正文为 0 字。

等待截止时间锚定首条准备好的消息，后续消息只会让截止时间提前。例如一条短消息原本等 15 秒，在第 4 秒收到第二条短消息，就只剩 6 秒，合计等 10 秒。若新增消息使缩短后的截止时间已经过去，则可立即处理。

同一会话批次开始至少间隔 **2 秒**，每批最多 **50 条**；最高上下文条数低于 50 时，批次上限同步降低，确保本批消息完整进入上下文。超出部分继续排队。模型执行和等待共享会话锁的时间计入合并等待，到期积压在上轮结束、满足最小间隔后处理。15 秒仅为空闲时的最大额外合并等待，不包含解析、模型执行和锁等待耗时。

正式回复的上下文首次唤醒默认回溯 **20 条**，持续活跃时固定起点增长，达到默认 **200 条**后保留最近的最大窗口滑动。再次被唤醒或回复会延续当前周期；接话窗口耗尽且本批及排队消息处理完毕、手动静默或会话安静至少 5 分钟后，下一次唤醒从最低窗口重新开始。最低和最高条数可在插件配置的「消息历史配置」中设置，前置决策仍固定读取 12 条历史。后台记忆与好感度维护共享最高条数上限，满窗封存片段、周期结束处理剩余消息，已处理消息不会因回溯重复维护。

决策不回复时，只完成本批消息，决策期间的新消息留到下一批。决策回复时，正式回复开始前的新消息可并入本轮，总数仍不超过 50 条；正式回复开始后的消息留到下一轮。不同会话可独立处理。

可在机器人配置的 **正式回复 → 复审模型（可选）** 中选择模型，留空关闭。开启后，普通回复生成期间有新消息入库时，在状态更新和动作派发前复审一次，仅判断待发送 `message` 内容与新消息是否冲突，不审核语音、图片或表情。通过则发送原草稿，新消息保留到下一批；拒绝则恢复原批次的未决策和待处理状态，保留原消息顺序、合并新消息并重新决策与生成，仍遵守 50 条上限。新内容直接发送，不因持续到来的消息重复复审；未并入的消息继续排队。每次逻辑回复独立计算一次复审机会。实际执行过原生工具或已进入后续工具轮次时跳过复审。复审模型超时（10 秒）或结果无效时默认放行。

在 **机器人管理 → 编辑机器人 → 正式回复 → 无效回复回退提供商（可选）** 中配置独立的备用模型顺序。留空关闭该功能，保持原有输出解析、空回复和重试规则，不增加请求。配置后，回复为空、仅有推理或没有可识别的回复 XML 标签时立即切换到该列表，保持原提示词和上下文，跳过本轮已尝试的提供商，不参与主列表随机选择。备用模型再次返回空输出、仅有推理或无可识别 XML 时立即结束，不再重试或切换模型；备用模型发生普通接口异常时仍沿用正式回复重试上限，耗尽后按列表尝试下一个模型。仅输出 `<status>` 的正常沉默和有效工具、媒体输出不触发回退；已执行原生工具时不会重放。启用该功能后未取得有效结果时记录失败。

需要减少主动接话时，可在机器人配置中调低“主动接话触发概率”或调小“接话分析窗口轮数”。完整消息边界与失败处理说明见[详细使用文档](../../DETAIL.md#会话批处理与消息边界)。
