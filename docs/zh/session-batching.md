# 会话动态批处理

Giftia 为同一 Bot、同一完整平台会话串行执行决策和回复。群聊、私聊及 `@` 使用相同的合并等待，不需要配置。

按当前已解析入队的消息条数和累计正文字符数分别查表，取较短的等待时间：

| 等待时间 | 消息条数 | 正文字符数 |
| --- | --- | --- |
| 15 秒 | 1 | 0～10 |
| 10 秒 | 2 | 11～30 |
| 6 秒 | 3～4 | 31～60 |
| 3 秒 | 5～7 | 61～100 |
| 1.5 秒 | 8～11 | 101～160 |
| 0.8 秒 | 12 及以上 | 161 及以上 |

正文取原始消息中的文字，忽略空白、`@` 账号与昵称、引用内容、媒体标识和生成的转述。QQ Markdown 提及的重复降级文本只统计一次。纯 `@` 或媒体消息仍各计一条，正文为 0 字。

等待截止时间锚定首条准备好的消息，后续消息只会让截止时间提前。例如一条短消息原本等 15 秒，在第 4 秒收到第二条短消息，就只剩 6 秒，合计等 10 秒。若新增消息使缩短后的截止时间已经过去，则可立即处理。

同一会话批次开始至少间隔 **2 秒**，每批最多 **50 条**，超出部分继续排队。模型执行和等待共享会话锁的时间计入合并等待，到期积压在上轮结束、满足最小间隔后处理。15 秒仅为空闲时的最大额外合并等待，不包含解析、模型执行和锁等待耗时。

决策不回复时，只完成本批消息，决策期间的新消息留到下一批。决策回复时，正式回复开始前的新消息可并入本轮，总数仍不超过 50 条；正式回复开始后的消息留到下一轮。不同会话可独立处理。

可在机器人配置的 **正式回复 → 复审模型（可选）** 中选择模型，留空关闭。开启后，普通回复生成期间有新消息入库时，在状态更新和动作派发前复审一次，仅判断待发送 `message` 内容与新消息是否冲突，不审核语音、图片或表情。通过则发送原草稿，新消息保留到下一批；拒绝则恢复原批次的未决策和待处理状态，保留原消息顺序、合并新消息并重新决策与生成，仍遵守 50 条上限。新内容直接发送，不因持续到来的消息重复复审；未并入的消息继续排队。每次逻辑回复独立计算一次复审机会。实际执行过原生工具或已进入后续工具轮次时跳过复审。复审模型超时（30 秒）或结果无效时默认放行。

插件设置中的“会话批处理”分组（`concurrent_config`）已整体移除，升级后的对应关系如下：

| 原设置（存储键） | 现在的行为 |
| --- | --- |
| 会话决策最小间隔（`group_throttle_time`） | 固定 2 秒 |
| 会话消息防抖（`user_debounce_time`） | 按消息条数与正文字符数自动选择 0.8～15 秒 |
| 会话最大合并等待（`user_max_debounce_time`） | 首条准备好的消息起最多额外等待 15 秒，后续消息不延长 |
| 每批待处理消息上限（`batch_max_messages`） | 固定 50 条，超出部分保留到下一批 |

旧值不再读取，无需迁移。需要减少主动接话时，可在机器人配置中调低“主动接话触发概率”或调小“接话分析窗口轮数”。完整消息边界与失败处理说明见[详细使用文档](../../DETAIL.md#会话批处理与消息边界)。
