# 原子记忆管理

在 AstrBot 插件页面打开 Giftia WebUI，进入“长期记忆”。默认只显示有效记录；“全部状态”可查看已完成、取消、过期和被替代的历史。

1. 选择 Bot 和会话，再按类型、状态、关联群友或内容筛选。关联群友使用完整账号精确匹配，点击卡片上的成员标签也能筛选。
2. 正文说明参与群友、各自行为、互动方向，以及群友自述或观察归纳等获知方式。卡片保留主题和观察时间，展开“查看依据”可阅读原话及来源记录。
3. “新增记忆”可选择五种类型并填写全部关联群友账号、主题和文本，支持多人参与。只有约定可以设置到期时间，输入时间按浏览器本地时区保存。新增后定位到对应会话和类型，记录标为人工录入。
4. “编辑”可修改内容、重要度和关联群友；有效约定可设为完成或取消。类型、主题与原话依据保留，内容修改标为人工修订。后台修改过的条目需要刷新后重新编辑。
5. “清理记忆”继承当前类型、状态、关联群友及内容条件，先预览候选再选择删除。

| 原入口 | 现在的入口 |
| --- | --- |
| 主体、对象字段 | 合并为关联群友账号列表，角色和互动方向由正文说明 |
| 来源分类筛选 | 已移除，自述和归纳推断由正文说明，原话证据仍可展开 |
| 自身的“记忆查询与删除”工具 | 改为“记忆查询”，删除由后台维护、管理页及管理员命令处理 |
| 画像中的关键约定 | 长期记忆 → 约定，保留独立状态和期限 |
| 画像中的性格、兴趣、补充与关系头衔 | 不再维护固定标签；有证据的事实按事件、关系、偏好或习惯管理 |
| 称呼、外号、互动态度、好感度、头像描述 | 继续在画像管理维护 |

成员卡片原来的“画像／关系”子页签已取消，保留信息直接展示。卡片不展示近期记忆；请在“长期记忆”按用户账号筛选相关记录。

![成员卡片直接展示保留信息](../images/member-profile.jpg)

旧画像字段仍保留在数据库中，用户画像报告不再读取和展示性格风格、兴趣话题、其他补充、关键约定和关系称谓。自定义报告模板若仍引用旧变量，需删除相应内容或恢复默认模板。旧版记忆继续保留，不会自动伪造原话证据；开发中的记忆结构直接采用当前定义，不迁移中间版本的主体、对象或附件级证据。记忆不再保存 `subject_id`、`object_id` 和 `origin`。定期归纳和整理仍由后台配置与管理员指令 `/强制总结`、`/整理记忆` 控制。

归纳和整理各自执行独立任务。归纳只记录本批新消息中的新事件或事实，不检索、合并或修改历史记忆。成功新增记忆后，程序持久化该批次并启动整理任务，逐条用新增记忆检索相关历史记忆；检索排除本批全部新增项和后续批次，历史候选包含旧格式、较早创建及已经整理过的记录。只有命中的新增项及其相关历史记录进入整理模型，共享历史记录去重后处理；没有命中的新增项本轮跳过，仍保留在记忆库中供后续召回。

整理召回逐条按新增记忆的关联群友筛选，历史记录至少有一名关联群友相同才进入候选，机器人自身不参与匹配。向量检索和文本匹配均在截取候选数量前应用该条件，类型不同的记忆仍可关联。旧记录缺少关联列表时回退读取 `user_id`，没有可用用户信息的记录跳过；关联用户有交集不代表可以直接合并，仍需核对事实及互动方向。

归纳模型只通过 `source_id` 引用消息，程序自动将该消息的直接发言及已完成的可用媒体转述合并为一份证据快照，同时保存发言账号、时间、消息标识和媒体标识；模型无需选择媒体或复述原文。一条消息包含多个媒体仍算一份独立来源。引用和转发中的嵌套内容不作为直接发言，撤回消息、操作日志、指令及不可用媒体不能作为依据。

插件升级、启动和定时检查不会把存量记忆自动加入整理队列；旧格式记录只有被新增记忆召回时才参与整理。检索失败或模型未返回内容时保留新增批次，后台每 5 分钟检查并重试。模型输出未通过校验时，会携带具体错误纠正一次；仍失败则暂挂该批次，保存输入、原始输出与错误详情，其他批次继续处理。可执行 `/整理记忆` 手动重试暂挂或待处理批次；`/强制总结` 仍只归纳未处理的新消息。未启用嵌入时使用文本匹配；检索失败不会当作无命中跳过。记忆、批次和处理进度在事务内保存，失败重试不会重复归纳。再次召回不算新证据，原始证据保存在记忆内，不依赖原消息继续保留。

归纳触发时机由“被动总结静默触发阈值”和“被动总结溢出触发阈值”控制，批次大小由插件自动控制。“单批记忆归纳消息上限”和“单批记忆整理条数”已从配置中移除，改为内部固定上限：每批归纳最多 100 条消息并按约 16000 字符划分完整消息，每批整理最多 60 条新增记忆。旧配置中的这两个批次字段不再生效，无需手动清理。

决策模型先判断是否需要检索；正式回复开启会话召回池时，还会用本批待回复消息自动检索。所有召回入口保留完整记忆记录，由同一个构建函数注入正文、类型及明确的事件时间、观察时段或约定截止时间。事件时间不明时只显示创建时的记录时间，不使用整理更新时间代替。记忆 ID、关联账号列表、证据原文和内部来源链不注入回复提示词；内部仍按 ID 去重，本轮召回优先于会话池中的副本。回复模型保留 `<search_memory>`，不再提供或执行 `<delete_memory>`，已有工具开关设置自动沿用。

正式回复、决策检索及记忆查询工具只排除 `superseded`（已被替代）的旧版本；`active`、`completed`、`cancelled`、`expired` 均可按相关性召回。注入正文时明确提供 `status`，已到期但尚未更新数据库的有效约定按 `expired` 呈现；已完成、取消或过期的约定作为历史事实，不能当作仍待履行的约定。会话召回池保留这些历史状态，缓存 TTL 和条数限制继续生效。索引随记忆修订正常更新，已被替代的版本从索引与提示词中排除。整理阶段仍只更新 `active` 记忆。

整理模型依据完整正文和证据判断事实是否一致，更新时明确指定内部记忆 ID，不再按参与者或主题自动定位目标。参与者相同或主题相似不能证明可以合并，互动方向相反的事件分别保留。程序校验来源和会话范围、修订冲突、重复操作及合法状态转换；从事件新归纳习惯仍需至少三条独立消息，既有习惯可携带原始证据继续更新。具体事实归属和自述与推断的区别由模型结合正文及证据判断。

聊天历史自动清理与按自动配置立即执行清理会保留归纳游标之后的待处理消息。缺少有效进度或归纳失败时不会越过保护边界；成功处理后再按时间、条数和最新消息保底条件清理。已保存在记忆内的证据摘录继续可用，清理原消息后仍可归纳习惯。

当前开发分支直接在建表语句中声明记忆类型、状态、期限和修订字段，不再提供旧记忆表的自动补列及索引版本回填；测试或开发库应使用当前表结构，初始化代码不会删除或重建已有数据。
